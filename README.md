# 八男杀 · 网页单机 Demo

一款可在浏览器里直接游玩的卡牌对战 Demo：**1 名玩家对 4 名电脑**，单机离线运行，无需联网、无需注册。

本仓库对应开发方案的**第一阶段（M0–M4）**交付：确定性规则引擎、完整 104 张基础牌、首发 8 名角色的真实技能、桌面界面、电脑策略、本地存档与回放。详细的开发与验收记录见 [`第一阶段交付与验收记录.md`](./第一阶段交付与验收记录.md)。

## 快速开始

### 环境要求

- **Node.js ≥ 20**（推荐 22；自对局脚本 `npm run sim` 使用了 `--experimental-strip-types`）
- 任意现代浏览器（Chrome / Edge / Safari / Firefox）

### 三步跑起来

```bash
npm install          # 安装依赖
npm run build        # 编译到 dist/（首次运行必须）
npm start            # 启动本地服务，默认 http://127.0.0.1:3000
```

然后在浏览器打开终端里打印的地址即可。

> `dist/` 被 `.gitignore` 排除，不在仓库里，所以 `npm start` 前**必须先 `npm run build`**。如果忘了，`npm start` 会提示「请先运行：npm run build」并退出。

### 只改代码时：开发模式

```bash
npm run dev          # 启动 Vite 开发服务器，带热更新，直接读源码，无需先 build
```

打开 Vite 打印的地址（默认 http://127.0.0.1:5173）即可。

### 局域网 / 自定义端口

```bash
PORT=3210 npm start            # 改端口
npm start -- --lan             # 监听 0.0.0.0，同一局域网内的手机/其他电脑可访问
```

服务带 `/healthz` 健康检查端点。

## 怎么玩

1. **开始页** → 点「新游戏（1 人对 4 名电脑）」。
2. **选将页** → 从 8 名已实装角色里挑一名作为你自己，点「确认选将并开始」。
3. 引擎随机分配**身份**（主公 / 忠臣 / 反贼 / 内奸），发初始手牌，进入对局。
4. 轮到你时，在出牌阶段**选牌 → 选目标 → 确认**；所有需要你决策的点（出牌、响应【闪】/【无懈可击】、选目标、弃牌）都由统一的弹层处理。
5. 结束阶段手牌超过体力上限的部分要弃掉。
6. 一名角色阵亡后，结算页会给出本局胜负与各方身份。

**托管与倒计时**：你思考时会有倒计时，超时后电脑会替你做出合法操作；开始页可关闭倒计时。刷新网页不会丢失牌局——本地会自动恢复上一局（IndexedDB 存档）。

### 胜负（5 人身份局）

- **主公 & 忠臣**：消灭所有反贼与内奸即获胜。
- **反贼**：消灭主公即获胜。
- **内奸**：先帮着清掉反贼和忠臣，最后亲手杀死主公才获胜（最难）。

> 引擎在测试中还覆盖了 4 / 6 / 7 / 8 人配置与对应身份分配，但当前 Demo 界面固定为 5 人单机。

## 工程结构

```
banan-sha-game/
├── index.html              # 页面入口
├── src/
│   ├── engine/             # 纯 TS 规则引擎（不依赖 React / DOM）
│   │   ├── drivers/        # 可序列化的结算栈（出牌、响应、弃牌…）
│   │   ├── rng.ts          # 确定性随机（xoshiro128**），状态进 GameState
│   │   └── ...
│   ├── content/            # 牌定义、角色定义、104 张配牌表
│   ├── web/                # React 桌面 UI、统一提示弹层、GameClient
│   └── worker/             # Web Worker 中运行的裁判进程
├── tests/                  # Vitest 测试（163 项）
├── scripts/
│   ├── serve.mjs           # 本地启动入口（静态托管 dist/）
│   ├── simulate.mjs        # 200 局确定性自对局 / 复现重放
│   └── gen-deck.mjs        # 配牌表生成校验
└── 第一阶段交付与验收记录.md
```

### 为什么是「确定性引擎」

- 规则引擎是纯函数式的：**不读系统时间、不调用 `Math.random()`**，所有随机性来自可序列化的 RNG 状态。
- 引擎跑在 **Web Worker** 里，UI 通过 `PlayerView`（白名单投影）只读自己该看的信息。
- 同一初始局面 + 同一串操作 + 同一份超时记录，重放后**最终状态哈希一定一致**——可用于复现 bug：卡死/报错时可「导出复现文件」交给开发者原样重跑。

## 开发 & 测试

```bash
npm run dev        # 开发服务器（热更新）
npm test           # 跑全部 Vitest 测试（163 项）
npm run test:watch # 监听模式
npm run build      # 类型检查 + 生产构建

npm run sim:replay # 导出上一局复现文件并重放，校验状态哈希一致
```
